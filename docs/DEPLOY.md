# Автообновление vivaacademy.md из GitHub

После настройки каждое изменение папки `academy/` в ветке `main` само выкладывается на сервер.
Workflow — `.github/workflows/deploy-academy.yml`. Настройка — один раз, примерно 15–20 минут.

## Что делает выкладка
- Проверяет синтаксис PHP-файлов.
- Копирует файлы сайта на сервер по SSH (`rsync`): только добавляет и перезаписывает, ничего не удаляет.
- **Не трогает** `api/config.php`, `api/install.php`, папку `data/` и базу данных.
- В конце проверяет, что сайт и API отвечают.

Пока секреты не заданы, выкладка пропускается с предупреждением — ошибкой это не считается.

## Настройка

### 1. Доступ к репозиторию
Владелец репозитория добавляет администратора: **Settings → Collaborators → Add people** (по логину GitHub). Этого достаточно, чтобы запускать выкладку и смотреть её журнал.

В личном репозитории секреты может вносить **только владелец**. Поэтому администратор готовит значения (шаги 2–4) и передаёт их владельцу, а владелец вносит их в шаге 5. Ключ создаётся только для выкладки: после внесения секрета сообщение с ним нужно удалить, а файл ключа — стереть.

### 2. Пользователь на сервере
Подойдёт пользователь, у которого есть права на запись в папку сайта. Рекомендуется отдельный, без sudo:

```bash
sudo adduser --disabled-password --gecos "" deploy
sudo usermod -aG www-data deploy
sudo chown -R www-data:www-data /var/www/vivaacademy.md
sudo chmod -R g+w /var/www/vivaacademy.md
sudo apt-get install -y rsync
```

Путь `/var/www/vivaacademy.md` замените на фактическую папку сайта.

### 3. SSH-ключ только для выкладки
На своём компьютере:

```bash
ssh-keygen -t ed25519 -C "github-deploy vivaacademy" -f vivaacademy_deploy -N ""
```

Содержимое `vivaacademy_deploy.pub` добавьте на сервере в `~deploy/.ssh/authorized_keys` (права: папка `700`, файл `600`, владелец `deploy`).

Проверьте вход: `ssh -i vivaacademy_deploy deploy@СЕРВЕР`.

### 4. Отпечаток сервера

```bash
ssh-keyscan -p 22 СЕРВЕР
```

Сверьте отпечаток с сервером (`ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`). Весь вывод `ssh-keyscan` пойдёт в секрет `DEPLOY_KNOWN_HOSTS`.

### 5. Секреты в GitHub (вносит владелец репозитория)
**Settings → Secrets and variables → Actions → New repository secret** — по одному секрету на каждую строку:

| Секрет | Значение |
| --- | --- |
| `DEPLOY_HOST` | адрес сервера (домен или IP) |
| `DEPLOY_PORT` | порт SSH, если не 22 (иначе можно не задавать) |
| `DEPLOY_USER` | пользователь, например `deploy` |
| `DEPLOY_PATH` | папка сайта, например `/var/www/vivaacademy.md` |
| `DEPLOY_SSH_KEY` | всё содержимое закрытого ключа `vivaacademy_deploy` |
| `DEPLOY_KNOWN_HOSTS` | вывод `ssh-keyscan` из шага 4 |

После этого удалите сообщение с ключом из переписки и файл `vivaacademy_deploy` с компьютера.

### 6. Первая выкладка
Администратор или владелец: **Actions → Deploy Viva Academy → Run workflow** (ветка `main`). Зелёная галочка — сайт обновлён. Откройте vivaacademy.md с очисткой кэша (Ctrl+F5).

## Если выкладка не прошла
- `Permission denied (publickey)` — открытый ключ не добавлен в `authorized_keys` нужного пользователя или неверный `DEPLOY_USER`.
- `DEPLOY_SSH_KEY повреждён` или `error in libcrypto` — ключ испорчен при копировании: внесите его заново целиком, лучше с компьютера. Переносы строк, лишние пробелы и «длинные» тире выкладка исправляет сама.
- В журнале выкладки печатается отпечаток ключа (`SHA256:…`). Сверьте его с ключом на сервере: `ssh-keygen -lf ~deploy_academy/.ssh/authorized_keys`.
- `Host key verification failed` — неверный или неполный `DEPLOY_KNOWN_HOSTS`.
- `rsync: command not found` — установите `rsync` на сервере.
- `Permission denied` при записи файлов — у пользователя нет прав на запись в папку сайта (шаг 2).
- Не прошла проверка «сайт отвечает» — файлы загружены, но сайт или PHP вернули ошибку: смотрите журнал ошибок Apache/PHP.

## Откат
Отмените изменение в GitHub (кнопка **Revert** в слитом PR) — выкладка запустится сама и вернёт прежние файлы.

## Учебные материалы (PDF, PowerPoint и видео)

Администратор загружает презентации на странице «Материалы». Файлы хранятся в базе данных сайта, в таблице `material_chunks`, частями по 512 КБ. Дополнительная настройка сервера не нужна: права записи на диск не требуются, а файлы попадают в резервную копию вместе с базой.

- Каждая часть меньше 1 МБ, поэтому стандартного значения `max_allowed_packet` в MySQL достаточно.
- 100 презентаций по 10 МБ займут в базе около 1 ГБ. Проверьте, что тариф хостинга это позволяет.
- Можно загружать PDF и PowerPoint (.pptx, .ppt). Для PowerPoint сайт сам делает PDF-копию, чтобы презентацию можно было открыть прямо в браузере; оригинал тоже доступен для скачивания.
- PDF делает задание `.github/workflows/academy-convert.yml`. Сайт запускает его сразу после загрузки презентации, если в кабинете руководителя подключён токен GitHub (fine-grained, только репозиторий CV-Inna-Shvets-, разрешение Actions: Read and write). Без токена задание идёт по расписанию, а GitHub выполняет расписание нерегулярно — иногда раз в несколько часов. LibreOffice ставится, только если есть новые презентации. Для доступа к сайту используется ключ `api/conv_key.php`: его создаёт выкладка из секрета `DEPLOY_SSH_KEY`, отдельно настраивать ничего не нужно. Если сменить ключ выкладки, сначала выполните выкладку, затем конвертер подхватит новый ключ.
- Если презентация не конвертируется (повреждённый файл), после трёх попыток сайт перестаёт пробовать, а на карточке остаётся кнопка «Скачать PowerPoint».
- Видео (.mp4, .mov, .webm, до 1 ГБ) хранится так же, в базе, и смотрится прямо на сайте с перемоткой (сервер отдаёт файл частями по заголовку Range). Видео заметно увеличивает размер базы: 10 роликов по 150 МБ — это 1,5 ГБ. Перед массовой загрузкой проверьте лимит базы на тарифе хостинга.
- Большие ролики удобнее добавлять ссылкой (поле «…или ссылка на видео»): Google Диск, YouTube, Vimeo. Такое видео смотрят во встроенном плеере, а в базе хранится только ссылка. На Google Диске нужен доступ «Все, у кого есть ссылка».
- Видео и презентации, привязанные к блоку «Ортопедия» (поле «Курс с тестом по этой теме»), появляются на странице раздела и на странице блока.

## Раздел «Ортопедия»

Четыре блока по ассортименту Крейт (`tools/ortho/*.js`) собираются в `js/data-ortho.js` командой `node tools/ortho/build.js && node tools/build-answers.js`. В каждом блоке 4 урока и тест из 20 вопросов, варианты ответов перемешиваются при сборке.

## Рейтинг продаж по акциям

Руководство присылает Excel с продажами по акциям (обычно 2 раза в месяц). Администратор загружает его кнопкой «Импорт продаж» в кабинете руководителя или «+ Загрузить продажи» на странице «Рейтинг продаж».

- Файл (.xlsx, .xls, .csv) читается в браузере библиотекой SheetJS (загружается с cdnjs только при импорте). Сайт сам находит строку заголовков и предлагает, что в какой колонке: ФИО, логин, аптека, акция, количество, сумма. Если акции идут отдельными колонками («сотрудники по строкам, акции по колонкам»), такие колонки отмечаются как «Продажи по акции». Строки и колонки «Итого» не загружаются.
- Сотрудники находятся по логину, затем по ФИО в любом порядке слов (при однофамильцах — по аптеке). Ненайденные остаются в рейтинге, но не видят свои продажи в кабинете; их список показывается после загрузки.
- Рейтинг считается по сумме продаж, если в файле есть суммы, иначе по количеству. Все сотрудники видят топ-10 и свои продажи (страница «Рейтинг продаж» и блок в личном кабинете); руководители — полный список с выгрузкой в Excel.
- Данные хранятся в таблицах `sales_periods` и `sales_rows` (схема 9). Повторная загрузка периода с тем же названием заменяет его.

### Рейтинг аптек (бланк руководства)

- Если загружен «Бланк» (лист с колонками «Бренд», «Номенклатура», «План на 1 фармацевта» и столбцами аптек) или итоговый отчёт с листами «Итог по аптекам» / «Зачёт по позициям», сайт строит **рейтинг аптек**.
- Расчёт: план аптеки = план на 1 фармацевта × число фармацевтов; «по количеству» = Σ min(факт, план) / план; итоговый % = среднее по товарным группам выполнения, ограниченного 100 %. Так же считаются бренды и позиции (зоны ≥ 50 %, 30–50 %, < 30 %).
- Сотрудник видит свою аптеку, если в профиле в поле «Аптека» указано «Аптека №N» или «ФП №N».
- Выгрузка из 1С без колонки плана отклоняется с подсказкой загрузить бланк.
- Данные хранятся в таблице `sales_reports` (JSON по периоду).

### Рейтинг продавцов (бланк с ФИО)

- Страница «Рейтинги» (`#/sales`) — три вкладки: «Обучение» (тесты), «Продавцы», «Аптеки».
- Бланк, где в колонках вместо аптек — ФИО сотрудников, распознаётся автоматически. Личный план = план на 1 фармацевта по каждой товарной группе; рейтинг — по тем же правилам, что у аптек.
- Аптека сотрудника берётся из файла (строка «Аптека» под заголовками, аптека в той же ячейке после ФИО — «Иванова Анна Петровна, Аптека №7» — или строка с аптеками над ФИО), иначе из профиля.
- Рейтинг аптек собирается из продавцов: план = план на 1 фармацевта × число продавцов аптеки, факт — сумма их продаж.
- Сотрудники находятся по ФИО в любом порядке слов, с отчеством или без. Ненайденные показываются после загрузки.
- Для обычной таблицы продаж без плана рейтинг аптек — сумма продаж её сотрудников.
- Понимает и «Бланк с процентами» (строка заголовков без «Бренд», колонка «на 1 фарм до …», рядом с каждым ФИО колонка «Процент», под ФИО — аптека, итоги групп строками «Итого: …»). Период подставляется из строки «Продажи на 25.11.26». Расчёт совпадает с листом «Фармацевты по алфавиту».

## Демо-доступ

Чтобы показать сайт посторонним, создайте в кабинете руководителя сотрудника с ролью «Демо». Такой пользователь видит интерфейс руководителя (кабинет, рейтинги, материалы, курсы), но:
- ФИО и логины сотрудников заменены на «Сотрудник №N», выгрузка в Excel недоступна;
- изменить ничего нельзя (профиль, пароль, сотрудники, загрузки, записи на мероприятия);
- уроки и тесты можно пройти — результат не сохраняется и сертификат не выдаётся.

Отключить демо-доступ — заблокировать этого пользователя.

## Инструкция по сайту

При первом заходе в браузере открывается инструкция — 13 слайдов с экранами сайта и озвучкой (кнопка «Слушать с голосом» листает слайды сама).
Потом она всегда доступна по кнопке «?» в правом нижнем углу. Видео целиком: `guide/vivaacademy-instrukciya.mp4` — его можно отправить сотрудникам в Telegram.
В меню есть пункт «Инструкция» (`#/help`): презентация для фармацевтов и — для руководителей, администраторов и демо-доступа — вторая, по кабинету руководителя (`guide/admin/`, видео `guide/admin/vivaacademy-rukovoditelyu.mp4`).
Как пересобрать слайды и голос — `academy/tools/guide/README.md`.
